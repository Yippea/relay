Vaultwork Relay

Three-party split custody — the seal, the sealed text, and the key never sit in one place.

A — Sealer Types the message. Never sees the sealed text or the key once sent.
B — Cipher holder Receives the sealed text only. Cannot read it without the key.
C — Key holder Receives the key only. Cannot read anything without the sealed text.
By design: once a message is sealed, this screen does not display the sealed text or the key — they route straight to B and C over their own connections. This tab only keeps a timestamped log of what was sent.

Each seal uses three layers of fresh, random AES-256 keys (GCM, then CBC+HMAC, then GCM again), wrapped with PBKDF2 (210,000 rounds) + AES-256-GCM. Sealing happens in the Sealer's browser tab before anything is sent. The sealed text and the key travel over separate peer-to-peer connections, so no single tab ever holds both. B and C would need to compare notes out of band to recover the original message.
